# 校园网设备告警监控中心 — 项目搭建与说明

---

## 一、项目概述

一个**校园无线网络智能运维原型系统**，模拟 10 台 AP 的实时监控，自动检测故障并用 AI 分析原因和修复建议。

**数据流：** Python 模拟指标 → Prometheus 采集存储 + 告警检测 → Grafana / 自研前端展示 → DeepSeek AI 分析

---

## 二、系统架构

```
Python 模拟器 (localhost:8000)  ← 10 台 AP 实时指标
       │ HTTP scrape 15s
       ▼
Prometheus (localhost:9090)  ← 时序存储 + 告警引擎
       │
       ├── Grafana (localhost:3000)  ← 专业监控面板
       └── 前端 dashboard.html       ← 5 屏单页应用 + AI 分析
                                          │
                                     Python /api/analyze
                                          │
                                     DeepSeek LLM
```

---

## 三、快速启动

```bash
# 1. 启动 Prometheus + Grafana
docker compose up -d

# 2. 启动数据模拟器（可选 LLM_API_KEY 启用 AI 分析）
export LLM_API_KEY="sk-xxx"
python scripts/generate_metrics.py

# 3. 浏览器打开 frontend/dashboard.html
```

| 入口 | 地址 |
|------|------|
| Grafana | http://localhost:3000 (admin/admin) |
| Prometheus | http://localhost:9090 |
| 前端 | frontend/dashboard.html |
| 原始指标 | http://localhost:8000/metrics |

## 五、数据模拟器（generate_metrics.py）

### 5.1 模拟指标

| 指标 | 含义 | 正常范围 | 告警阈值 |
|------|------|----------|----------|
| ap_status | 在线状态 | 1 | = 0 离线 |
| client_count | 用户数 | 20-100 | > 150 |
| channel_utilization | 信道利用率 | 20-60% | > 80% |
| rx_errors_total | 接收错误 | 累计值 | rate > 5/s |
| ap_memory_usage_percent | 内存使用率 | 30-70% | > 85% |

### 5.2 模拟逻辑

- **上课/下课流量**：不同区域不同高峰时段（教学楼→上课，食堂→饭点）
- **异常注入**：AP 离线 2-15%、信道干扰 2%、内存泄漏 2%、用户数异常 3%
- **输出格式**：标准 Prometheus 文本格式

---

## 六、告警规则

| 告警 | 表达式 | 持续时间 | 等级 |
|------|--------|----------|------|
| APOffline | ap_status == 0 | 30s | Critical |
| ClientCountAnomaly | client_count > 150 | 30s | Warning |
| ChannelHighUtilization | channel_utilization > 80 | 30s | Warning |
| HighRxErrors | rate(rx_errors_total[1m]) > 5 | 30s | Warning |
| HighMemoryUsage | ap_memory_usage_percent > 85 | 1m | Warning |

## 七、前端设计（重点）

### 7.1 设计风格 — 赛博朋克风

整体视觉采用**深色赛博朋克风格**，以青色（`#00FFFF`）为主色调，配合暗色背景和发光效果，营造科技感和沉浸式监控体验。

**色彩系统（CSS 变量）：**

```css
:root {
  --cyan: #00FFFF;     /* 主色调—科技感、选中状态 */
  --red: #FF0000;      /* Critical 告警—危险 */
  --orange: #ff8c00;   /* Warning 告警—警告 */
  --green: #00d474;    /* 正常状态—健康 */
  --bg: #08081a;       /* 深色背景—赛博朋克基底 */
  --text2: rgba(255,255,255,0.4);  /* 次级文字 */
  --text3: rgba(255,255,255,0.2);  /* 辅助文字 */
}
```

### 7.2 布局结构

单页滚屏设计，顶部固定导航栏，底部 5 屏通过滚轮/触摸/导航切换：

```
┌─────────────────────────────────────────┐
│ [Logo] HOME  LIST  TOPOLOGY  AI  PROJECT│ ← 固定顶栏，告警时变色
├─────────────────────────────────────────┤
│                                         │
│  屏 0: HOME      全局状态概览            │
│  屏 1: LIST      AP 列表 + 告警         │
│  屏 2: TOPOLOGY  拓扑图                  │
│  屏 3: AI CORE   AI 分析                │
│  屏 4: PROJECT   项目介绍 + 粒子动效     │
│                                         │
└─────────────────────────────────────────┘
```

### 7.3 视觉亮点

| 设计元素 | 实现方式 | 效果 |
|----------|----------|------|
| **青色流动光带** | CSS 动画 + 渐变 | 页面左右两侧的流动光带，增强科技氛围 |
| **动态粒子背景** | Canvas 2D | 页面 4 的「SZU」粒子汇聚动效，鼠标靠近排斥 |
| **脉冲光环** | CSS 关键帧动画 | 拓扑图中告警/离线节点的周期性光环扩散 |
| **发光文字** | text-shadow | 导航选中项的青色发光效果 |
| **玻璃态卡片** | background: rgba + 边框 | 半透明暗色卡片，毛玻璃质感 |
| **渐变过渡** | 背景渐变 + 过渡动画 | 页间切换的渐变光晕 |
| **音乐播放按钮** | CSS 旋转脉冲动画 | 右上角圆形播放器，播放时脉冲发光 |
| **顶栏告警变色** | JS 动态控制 | 无告警=青色，Warning=金色，Critical=红色 |

### 7.4 五屏详解

**屏 0 - HOME：**
- 左上角显示 AP 在线率（大数字+环形进度条）
- 右上角实时数字时钟（时:分:秒 + 日期）
- 四张指标卡片：活跃告警数、在线 AP、总用户数、拥塞/高内存计数
- 底部装饰性青色流动光带

**屏 1 - LIST：**
- 上半：10 台 AP 卡片列表，每张显示名称、IP、位置、用户数/信道/内存
- 超标值红色高亮，信道/内存条形图（红/橙/绿三色）
- 下半：活跃告警列表，每条左侧色条标识等级（红=Critical 橙=Warning）
- "无告警"状态显示"—— NO ACTIVE ALERTS ——"占位文字

**屏 2 - TOPOLOGY：**
- D3.js 力导向拓扑图，节点可拖拽
- 三层结构：CORE SW（中心）→ DIST SW（环绕）→ 10 AP（最外圈）
- 五态颜色编码：紫色（核心）、青色（汇聚）、绿色（正常）、橙色（告警）、红色（离线）
- 告警/离线节点有脉冲光环，在线节点无光环
- 节点带 emoji 图标（🌐🔀🔴🟡🟢）

**屏 3 - AI CORE：**
- 告警下拉选择器 +「AI 分析」按钮
- 分析结果分段展示（原因/影响/修复/预防）
- 底部标签：AI · DEEPSEEK · REALTIME

**屏 4 - PROJECT：**
- 项目描述文字 + Canvas 粒子动效背景
- 「SZU」字母由数百个粒子动态汇聚而成
- 鼠标移动时粒子产生排斥效果

### 7.5 交互细节

- **导航反馈**：点击时立即切换，当前屏对应的导航项高亮为青色
- **悬停效果**：AP 卡片、告警条目、音乐按钮等均有变色/发光过渡
- **空状态处理**：无告警时显示友好占位文案，非空白
- **加载状态**：AI 分析进行中显示 "ANALYZING" 动画
- **错误状态**：AI 分析失败显示错误原因，非白屏
- **拓扑交互**：节点可拖拽，点击告警节点自动跳转 AI 分析

## 八、AI 分析

```bash
export LLM_API_KEY="sk-你的deepseek-api-key"
```

前端点「AI 分析」→ Python 调 DeepSeek API → 返回四部分：
1. 可能原因
2. 影响范围
3. 修复建议（按优先级）
4. 预防措施

未配置 API Key 不影响监控，仅 AI 分析不可用。

## 九、常见问题

**Q：数据是真的吗？**
模拟的，但格式是标准 Prometheus 格式，换成真实 AP 只需改数据源。

**Q：10 台 AP 够吗？**
Demo 足够。Prometheus 单机支持上万指标序列。

**Q：需要 npm 构建吗？**
不需要，纯 HTML + CSS + JS，D3.js 通过 CDN 引入，双击直接打开。
